2026年8月，有两条开源 AI 新闻放在一起看才有意思。

第一条：8月3日，阿里发布 Qwen3.8-Max，总参数2.4万亿、95B激活、1M上下文，Max级旗舰首次开源。更抢眼球的是它做了什么——从空文件夹开始，连续运行约16天、留下265次提交，自己写出了一个真实可用的 Agent 框架。整个过程没有人干预。

第二条：8月13日，DeepSeek 开源 Agent 运行时 DeepSeek Harness（简称 DSH），5天内 GitHub Star 冲破17万，8月20日即推出 RC.8 版本。OpenAI 随后在同一天将 Codex 定义为「开放的 Agent Harness 平台」——字面上，两家在同一周内对同一个技术方向给出了自己的命名和判断。

两件事没有事先协调，却指向同一个结论：**开源 AI 的叙事正在换档，从「追赶闭源」切换到「交付竞赛」**。

## Qwen3.8-Max：超大杯首次开源意味着什么

过去几年，国内开源模型的惯例是「开源中杯、闭源大杯」——最强的那款留着卖 API，开源出来的是次一档。Qwen3.8-Max 把这件事翻了过来。

总参数2.4万亿，激活95B，原生视觉理解，1M 上下文窗口。最重要的指标不是参数规模，而是 IFBench 的82.8分——这是一项指令遵循测试，衡量的是「你说什么，它就做什么」的能力，模型再聪明，如果无法精确执行结构化指令，在自动化流水线里就不可用。Qwen3.8-Max 在这项上的得分是82.8，Claude Opus 5 High 是63.5。

真正值得记录的是「16天事件」。这个基座模型在无人干预的情况下连续运行16天，从空仓库开始自主构建出一个可用的 Agent 框架，265次提交，完整的 Git 历史。这不是「补全代码」，是「交付项目」——国产大模型的能力叙事在这里换了一个量级。

开源权重已于8月10日当周通过 Hugging Face 和 ModelScope 公开下载。同时公开的还有 Qwen3.8-27B 版本，适合在消费级硬件上做本地部署。

## DeepSeek Harness：17万 Star 不是重点，插件架构才是

DeepSeek Harness 的核心设计哲学是一句话：**Model + Harness = Agent**。模型负责推理，Harness 负责编排——管理会话状态、上下文窗口、工具调用、沙箱隔离和人工审批。Harness 本身不做推理，它是大模型与真实任务之间的「工程外壳」。

技术细节上有几件事值得关注：

**一切皆插件。** DSH 基于 Cordis 元框架构建，模型、工具、技能、会话、沙箱、存储、循环、调度、UI——全部是可独立加载、卸载、替换的插件。这意味着企业可以把框架私有化部署，并无缝换用 OpenAI、Anthropic 等第三方模型，框架先行，不绑定特定模型。

**四种运行模式。** 标准模式提供完整工具集；PTC 模式让模型编写代码来组合工具调用；极简模式只有 shell 和文件编辑两个工具，用于基准测试；创造模式检查运行时并在内存中组合新模式。四种模式共享同一底座，本质是预设的插件集合快照。

**追记式会话日志。** 每一次运行都有迹可循：模型看到的一切——系统提示词、思维链、工具调用与结果、子 Agent 调度、上下文注入——全部写入 append-only 日志。出错时可以精确回放每一步发生了什么，而不是靠猜测。

RC.8 版本值得关注的一个变化：Claude Code 和 Codex 被纳入 DSH 的 Agent 编排体系——两者都作为 Profile Bundle 按需安装，作为子代理被 Harness 调用。这条路线在 RC.7 中已初现雏形，RC.8 进一步落实。DSH 正在把自己变成一个「统一调度层」：上层负责拆任务和编排工作流，底层可以根据任务需要把不同 Coding Agent 拉进来干活。

## 反共识视角：开源的「超越」不是发生在跑分榜上

这两条新闻的媒体叙事大多是「国产模型又追上了」「开源首次超越某闭源模型」——这种说法容易误导。

实际情况是：**开源在某些垂直维度已经领先，而不是全面超越**。

Qwen3.8-Max 在 IFBench、PaperBench 等特定基准上确实领先，但在 TextArena 综合排名上仍落后于 Anthropic 系列，CodeArena 排名全球第四（部分媒体称第三，以官方口径为准）。DeepSeek Harness 的插件架构在可观测性和可组合性上走出了独立路线，但作为一个 v0.1 早期预览版，生产可用性还不建议用于生产环境。

真正值得注意的转变发生在叙事层面：

过去开源 AI 的主要故事是「追赶」——参数量追不上、多模态能力跟不上、推理质量有差距。2026年8月的这几个项目展示出一种不同的方向感：**在特定垂直维度上，开源已经成为引领者**。Qwen3.8 用27B参数超越了自家更大规模的前代模型；DeepSeek Harness 的插件可互换性设计走出了与 LangGraph、AutoGen 完全不同的路线；Hugging Face 的开发者生态调查显示 Qwen 系列是社区中最常见的基础模型选择。

这不是「够用的替代品」，而是各自方向上的代表作。

## 巨头的选择：同一天，同一个方向

8月20日，DeepSeek Harness RC.8 发布。同一天，OpenAI 发布博客《Codex as a platform: build on the open agent harness》，将 Codex 从 AI 编程工具重新定义为「开放的 Agent Harness 平台」。

这不是巧合。两家在同一周内对「Harness」这个技术方向给出了自己的命名和判断，说明这不是某个实验室的特立独行，而是整个行业在模型能力趋同之后的共同转向：**模型不再是护城河，Harness 才是下一阶段的竞争焦点**。

类比一下：安卓和 iOS 的竞争最终不是在「芯片性能」上分胜负，而是在「生态和开发体验」上。AI 行业的竞争逻辑正在从「模型有多强」迁移到「基于这个模型能搭建什么样的应用体系」。

## 接下来看什么

**1. Qwen3.8-Max 开源权重实际表现**。官方跑分有参考价值，但真实工程场景下的稳定性——长程任务的可重复性、工具调用的准确率、长上下文的上下文管理——需要社区的真实反馈。关注 Hugging Face 和 GitHub 上的实测报告。

**2. DeepSeek Harness 的生态扩张速度**。发布后一周内，国家超算互联网、腾讯QQ、企业微信、阿里云、企查查等平台宣布接入 DSH。这个速度是否可持续，以及企业级私有化部署的实际落地情况，是判断 DSH 是否能真正挑战 LangGraph 生态的关键。

**3. OpenAI Codex 平台化的实际效果**。OpenAI 把 Codex 定义为「平台」而不是「工具」，意味着它在尝试做一个类似 DSH 的 Harness 层，但走的是闭源路线。开发者是否买单，取决于平台化的实际收益——把 Codex 的 Agent 能力接入企业已有系统，这件事的易用性决定了它能走多远。

**4. 「交付竞赛」的隐性成本**。Qwen3.8-Max 的「16天事件」是一个令人兴奋的叙事，但它同时提出了一个问题：AI 自主交付项目的可靠性边界在哪里？如果一个框架能在16天内完成265次提交，它的失败模式是什么？下一次自主运行会不会在第3天就卡住？这类问题在生产环境里比跑分排名更影响实际采用决策。

## 小结

2026年8月的这两周记录了一件事：开源 AI 正在越过「替代品」的叙事阶段。不是所有维度都领先，但在参数效率、Agent 基础设施、插件架构这些方向上，中国实验室正在成为真正的创新者而不是追随者。

这场竞争的下一章不在模型榜单上，在 Harness 层——谁能让大模型真正进入真实工作流，谁就拿到了下一阶段的主动权。
